# Isolated Windows evidence publication

The operator explicitly approved the dedicated VM write deploy key for `SpecimenArchive/Specimen-Archive` on 11 September 2026, with the recorder restricted to `specimen-records`. The key was registered as deploy-key ID 163030909. A GitHub deploy key technically grants repository-wide Git write access; the isolated service's code fixes its destination to the evidence branch. It never force-pushes, deletes branches or changes/bypasses branch protection.

`SpecimenArchive-Publisher` is a separate Windows Task Scheduler service running as SYSTEM, at startup, with one-minute failure recovery and one instance. Its private key, SSH configuration, verified GitHub host key, private bare object store and bundled executable are under `C:\ProgramData\SpecimenArchivePublisher`. A SYSTEM-only DACL removes inherited station-account and administrator access. The controller's station account was actually tested with `File.OpenRead`: access was denied. The browser receives no key, credential path or publication control endpoint. The service reads completed compact JSON records and writes publication receipts; the controller does not run a publisher.

The executable is self-contained: `npm run package:recorder` bundles `scripts/windows/record-service.ts` into `runtime/upgrade/record-service.mjs`. SYSTEM does not load modules from the controller-writable checkout. The deployment copies this reviewed bundle and `scripts/windows/start-record-service.ps1` into the private service directory using the SYSTEM installer, then protects them. Rebuilding the project alone does not replace the running publisher. Service upgrades require the same explicit administrator deployment procedure.

The private configuration supplies `enabled: true`, `isolation: remote-vm`, the exact repository and branch, `recordsRoot: C:/SpecimenArchive/runtime/exhibit-publications`, private object directory/SSH command and a non-secret status directory. It is not tracked. Do not paste it or the private key into chat or Git. Existing service installation helpers are in `scripts/windows/install-record-service.ps1`; they expect reviewed staging files under `runtime/remote-worker` and run as SYSTEM. Remove temporary installer tasks after successful installation.

Verification: the service published and read back real episode records. Commit [3acbd5a](https://github.com/SpecimenArchive/Specimen-Archive/commit/3acbd5ac6cd2f230bfb30ddd34ea1e35e378a2f4) was independently checked through GitHub: its only changed file is `experiments/exhibit_1789163381035_20ebda64.json`, added normally. Eight records had verified receipts by 22:40:53 UTC. Historical execution errors remain errors; their successful publication does not change their outcome.

Raw PNGs, compressed neural traces and videos remain on the VM under bounded retention. Publication reads/writes a separate bare Git store and cannot dirty the deployed source checkout. Lost receipts recover the original matching commit; conflicting record bytes are refused. Each pass attempts at most four records, with five attempts maximum per failed record and capped exponential backoff. A normal non-fast-forward push conflict is retried at most three times; no force option exists.

The current source also supports a private stop marker and recovery of a uniquely identified lock whose owner the OS confirms has exited. Active or unverifiable locks remain protected. The crash/lost-receipt test passes locally. These later changes are not yet installed on the VM. The first installed bundle predates cooperative stop; its next upgrade requires a controlled idle-service maintenance stop before running the installer. Do not replace files while a Git publication is active.
